# Demo 脚本（答辩/面试演示）

**系统**：EduTutor —— 基于 LangChain 的智能体记忆增强系统（个性化教育辅导）
**演示准备**：后端 8000 + 前端 3000 已启动，数据已清理（仅保留演示学生）

---

## 一、30 秒故事（开场用）

> 大模型智能体有个致命缺陷：**没有跨会话记忆**——每次对话都是"失忆的陌生人"。
>
> 我做了一套**记忆生命周期管理系统**：提取→存储→检索→更新→遗忘。
> 以个性化教育辅导为例：AI 辅导老师能**记住每个学生**的薄弱点、错题、学习偏好，
> 按**艾宾浩斯遗忘曲线**主动安排复习，配合**学科知识图谱**规划学习路径。
>
> 评测结果：相比无记忆基线，**个性化程度提升 2.83 分**（4.33 vs 1.50），
> 记忆检索 Hit@3 达 100%。这就是我今天演示的系统。

---

## 二、5 分钟演示流程

### 0:00-0:30 开场（30 秒故事，见上）

### 0:30-1:30 辅导对话页（核心：记忆可视化）
1. 打开 http://localhost:3000 → 辅导对话页
2. 选择演示学生（v03验证）
3. 输入："老师，帮我讲讲一元一次方程的移项，我总搞错"
   - **讲点**：AI 回答后，右侧"学生记忆"面板**实时刷新**，出现新的记忆卡片（"薄弱点：移项"）
   - **讲点**：这就是记忆提取——每轮对话结束，LLM 自动抽取值得长期记住的信息
4. 点"新会话"，再问："你还记得我上次最怕什么吗？"
   - **讲点**：新会话、无历史上下文，但 AI 能答出"你上次最怕解方程移项"——**跨会话记忆生效**

### 1:30-2:30 学生管理页（画像可视化）
1. 切到学生管理页
2. **讲点**：演示学生的画像卡片——薄弱点标签（红色）、已掌握（绿色）、雷达图
3. **讲点**：画像不是手填的，是系统从对话里**自动学习**的

### 2:30-3:30 知识图谱页（双引擎协同）
1. 切到知识图谱页
2. **讲点**：113 个知识点、223 条边、连接率 92.9%——这是从**人教版数学课本 PDF 自动编译**出来的
3. 点击一个知识点（如"绝对值"）
   - **讲点**：每个知识点有讲解、公式、难度、前置/相关链接
4. **讲点**：记忆和知识图谱是连通的——学生的薄弱点自动关联到图谱上的知识点（双引擎桥）

### 3:30-4:15 记忆库页（遗忘曲线 + 复习调度）
1. 切到记忆库页
2. **讲点**：记忆卡片列表 + 遗忘曲线图（4 条不同强度的衰减曲线）
3. 点一条记忆的"复习✓"
   - **讲点**：复习成功 → 记忆强度上升（0.6→0.83）→ 遗忘变慢 → 下次复习间隔翻倍（1天→2天）
4. **讲点**：这就是艾宾浩斯遗忘曲线驱动的复习调度——系统会"科学地忘"，在快忘时提醒复习

### 4:15-4:45 学习报告页（收尾）
1. 切到学习报告页
2. **讲点**：待复习计划（到期任务）+ 错题本 + 薄弱点摘要

### 4:45-5:00 收尾（讲结果）
> 四组评测：提取 F1=0.68（召回 0.85）、检索 Hit@3=100%、
> 消融实验个性化 +2.83、遗忘机制验证有效。全部可复现。

## 三、答辩可能被追问 & 应答要点

| 追问 | 应答要点 |
|------|---------|
| 记忆和 RAG 有什么区别？ | RAG 每次查询重新检索文档；本系统用 LLM Wiki 编译一次成互链知识图谱，且记忆是跨会话动态积累的画像 |
| 为什么用 MySQL + Chroma 双存储？ | 结构化画像/关系入 MySQL（可查询、可溯源），语义检索入向量库（相似度召回），工业标准混合架构 |
| 遗忘曲线参数怎么定的？ | λ 可配置（默认 0.1），评测四做了 λ 对比（0.05/0.1/0.2），SM-2 间隔翻倍是认知科学验证过的 |
| 提取的 F1 只有 0.68？ | 召回 0.85 说明该记的都抓到了；精确率低是过度提取，优化方向明确：置信度阈值过滤 + prompt 收紧（已列入展望） |
| 有没有用户真实评测？ | 当前是模拟场景评测（可复现），真实用户实验列入展望；评测数据集全部开源在仓库 |
| 代码是你自己写的吗？ | 是，从 v0.1 到 v0.5 迭代开发，每个模块有测试（16 个 pytest 用例），详见 GitHub |
