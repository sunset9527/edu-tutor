# EduTutor v1.5 记忆智能与个性化路径设计

## 1. 目标与边界

v1.5 完成三条闭环：可解释记忆检索、学习行为驱动的记忆更新、基于真实证据的个性化学习路径。范围以《个性化教育-产品迭代路线图》8.1～8.3 为准。

本版本不实现 SSE、会话历史查询页、前端事件流和报告时间序列；这些属于 v1.6。

## 2. 设计选择

### 2.1 可解释检索

保留画像、向量相关记忆、最近情景事件三路召回，并为每路设置独立限额。向量候选使用统一评分：

```text
final_score =
  w_similarity * similarity
  + w_recency * recency
  + w_retention * retention
  + w_confidence * confidence
```

- `similarity`：Chroma 余弦距离转换为 `clamp(1 - distance, 0, 1)`。
- `recency`：按最后访问时间、最后复习时间或创建时间计算指数衰减。
- `retention`：沿用遗忘曲线服务的保留率。
- `confidence`：记忆入库置信度。
- 四项权重在运行时读取系统配置，归一化后参与计算；响应追踪同时保存原始配置和实际归一化值。
- 初始权重只是工程默认值，验收文档不得声称它们是评测最优值。权重对比留给有固定验证集的评测任务。

检索结果新增 `trace`，记录候选记忆 ID、四项分数、最终分数、排名、是否采用和未采用原因。只有最终命中的记忆更新 `last_accessed_at`。画像、相关记忆和最近事件之间按记忆 ID 去重。

### 2.2 记忆更新与整合

掌握度采用有限状态：`不懂 → 基本会 → 熟练 → 精通`。正确练习前进一步，错误练习后退一步。每个学生和知识点只维护一条 active 掌握状态记忆，并同步可读内容、结构化事实、向量和知识点复习计划。

错题写入触发失败事件；错题标记掌握触发成功事件。失败把知识点复习任务安排到基础间隔后，成功延长间隔。所有变化均由数据库事实触发。

`有效策略`先作为 procedural 候选保存。相同策略收到的独立证据达到 `consolidation_threshold` 后才激活、写入向量库并创建复习计划，避免一次 LLM 提取直接固化为长期教学策略。

每条对话提取记忆时，在 `structured_data.provenance` 保存：来源会话 ID、来源消息 ID、提取版本和模型名。现有字段 `source_session_id`继续保留，避免为可表达在 JSON 中的元数据增加数据库迁移。

新增显式结束会话接口。结束时从数据库消息生成可复现的提取式摘要，写入 `sessions.summary`，并生成一条带溯源信息的 episodic 记忆。重复结束同一会话保持幂等。

LangGraph 不保存可恢复业务状态。每轮开始从 MySQL `messages` 重建短期上下文，跨会话信息从 MySQL/Chroma 长期记忆获取；因此 MySQL 是唯一恢复来源。

### 2.3 个性化学习路径

路径接口必须同时接收当前用户拥有的 `student_id` 和目标知识点 ID。服务只使用以下证据：

- `prerequisite` 图谱边；
- 学生的 active 掌握状态记忆；
- 未掌握错题次数；
- 到期知识点复习任务；
- active 薄弱点记忆。

路径保持前置知识的拓扑顺序。已达到 `熟练` 或 `精通` 且没有未掌握错题、到期复习或薄弱证据的前置节点可以跳过；目标节点始终保留。每一步返回 `reasons`、`mastery`、`wrong_count`、`review_due` 和 `evidence`。

图谱没有任何前置证据时，系统只返回目标节点，并在 `evidence_gap` 明确说明没有可靠前置关系，不调用 LLM 猜测前置知识。

## 3. API 变化

- `GET /api/knowledge/path/{kp_id}?student_id={id}`：返回个性化路径和证据缺口；要求登录并校验学生归属。
- `POST /api/sessions/{session_id}/end`：结束会话、生成摘要并写入情景记忆；要求登录并校验会话归属。
- `GET/PUT /api/settings`：增加四项检索权重、三路限额和新近度衰减天数。

已有 `/api/chat` 响应格式保持兼容。检索追踪先作为后端服务结果和验收证据提供，v1.6 再进入前端事件流。

## 4. 失败处理与一致性

- Chroma 不可用时，对话仍可使用画像和最近事件；追踪中标记向量召回错误。
- 掌握状态和 procedural 激活发生向量写入失败时回滚数据库事务，并恢复旧向量。
- 会话摘要写入失败时不设置 `ended_at`，客户端可以重试。
- 路径中找不到目标知识点返回 404；学生不属于当前用户也按现有约定返回 404。

## 5. 测试与验收证据

先写失败测试，再实现：

1. 统一评分、权重归一化、排名、拒绝原因和访问时间更新。
2. 正确/错误练习的掌握度状态转换与复习任务变化。
3. procedural 记忆达到阈值前后状态变化。
4. 会话摘要幂等、溯源完整、MySQL 历史恢复。
5. 三名学生面对同一目标时生成不同路径，且每项差异可以追溯到数据库记录。
6. 既有离线测试、前端类型检查和生产构建继续通过。
