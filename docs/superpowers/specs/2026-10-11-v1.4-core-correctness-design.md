# EduTutor v1.4 核心正确性设计

## 目标

完成产品迭代路线图中 v1.4 的全部范围，并用自动化测试、前端构建、双库审计和验收报告证明结果。

## 记忆与复习

- 未复习记忆从 `created_at` 开始衰减，复习后从 `last_reviewed_at` 开始衰减。
- 成功复习完成当前计划并生成下一条待办；失败复习保留当前待办并重置间隔。
- 学习报告只把 `pending` 且 `next_review_at <= now` 的计划计为到期。
- `薄弱点`、`已掌握`、`学习事件`、`错题`、`有效策略`是多值事实；`年级`、`学习偏好`是单值事实。
- 多值事实允许并存；同一知识点的“薄弱点/已掌握”互相冲突；单值事实的新值覆盖旧值。
- 低于 `extract_min_confidence` 的候选记忆不写入。

## MySQL 与 Chroma 一致性

- 新建记忆先写 MySQL 事务，再写 Chroma；任一步失败都回滚数据库并清理本次已写向量。
- 编辑内容时更新向量；归档、删除和冲突淘汰旧记忆时删除向量。
- 数据库提交失败时执行反向向量补偿。
- 审计脚本默认只报告缺失向量、孤儿向量、metadata 错误和失效知识点关联；仅 `--apply` 执行修复。
- 知识图谱重编译后，只重新关联原先指向被替换知识点的记忆。

## 账号隔离

- 学生、会话、记忆、复习计划、错题和报告均从 Bearer token 获取当前用户。
- 缺少或无效 token 返回 401；访问其他用户数据返回 404，避免泄露资源是否存在。
- 学生列表不再接受客户端传入的 `user_id` 作为授权依据。

## 前端

- 报告页加载并显示真实报告汇总。
- 图谱详情页提供学习路径按钮和路径步骤展示。
- `vue-tsc --noEmit` 成为生产构建前置步骤。

## 验收

- 后端离线单元测试、账号隔离集成测试通过。
- 连续三次成功复习后仍有待办，间隔为 8 天。
- 三个薄弱点可以同时保留，单值冲突进入冲突记录。
- 双库修复后缺失向量和孤儿向量均为 0。
- 前端类型检查和生产构建通过。
- 结果记录在 `docs/releases/v1.4/acceptance.md`，路线图状态更新为已完成。
