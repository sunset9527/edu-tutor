# EduTutor v1.7～v2.5 路线图重排设计

日期：2026-10-12

## 1. 目标

把功能扩张放在可复现评测和最终交付之前，并补齐当前产品最关键的三个缺口：新学生冷启动、真实练习闭环、教学回答的证据与纠错。

新路线必须保持版本号连续、每版可独立验收，并继续遵守数据诚信规则。原 v1.7 评测范围整体后移到 v2.4，原 v1.8 最终交付范围整体后移到 v2.5。历史已完成版本 v1.4～v1.6 不改名。

## 2. 排序原则

1. 先治理知识来源，再让知识进入诊断、练习和多角色产品功能。
2. 先完成学生学习闭环，再扩张家长端和教师端。
3. OCR 服务于作业进入练习闭环，不建立独立且不可确认的数据旁路。
4. 全学段和全学科按发布包验收，不能用知识点总数代替质量。
5. 评测放在功能冻结之后，评测数据集对应最终产品行为。
6. 部署、论文和作品集使用评测版本生成的事实，不手工复制数字。

## 3. 最终版本顺序

### v1.7 — 教材、知识库治理与回答证据

范围：

- 教材、学科、年级、册次、出版社、版本、文件哈希和许可来源显式建模。
- 编译任务支持预检、断点续跑、失败重试、staged/active 状态、审核、激活和回滚。
- 知识点保存来源文件、页码或内容区域；抽样审核覆盖正文、公式、前置边和难度。
- 个性化回答返回使用的知识点、记忆 ID 和分数摘要；没有足够证据时明确提示。
- 学生可反馈知识错误、题目错误、讲解错误或记忆错误，进入待确认纠错队列。

验收：一册教材可完整执行预检、编译、审核、激活、引用和回滚；回答证据能回到知识点及教材来源，纠错不会直接覆盖正式数据。

### v1.8 — 诊断测评、学习目标与个性化计划

范围：

- 新学生建立学习目标、目标日期、每周可用时间和学科范围。
- 诊断测评题目绑定知识点，保存作答、得分、耗时和置信度。
- 诊断结果形成初始掌握度，区分“没有证据”和“确认不懂”。
- 根据目标、前置图谱、掌握状态和可用时间生成可解释学习计划。
- 计划支持调整、暂停、重新计算和版本记录。

验收：一个无历史记忆的新学生可以完成诊断并得到可解释计划；重复诊断或修改目标不会破坏历史记录。

### v1.9 — 真实练习闭环与学习任务中心

范围：

- 题目生成后形成题目实例，学生可以正式提交答案。
- 客观题使用确定性规则判分；主观题和解析不确定项进入学生自评或人工确认。
- 错误答案生成错因、订正和同知识点再练任务，确认后才更新错题和画像。
- 正确、错误、订正和再练结果统一驱动掌握度及复习计划。
- 任务中心汇总今日学习计划、到期复习、待订正、再练和已完成记录。

验收：完成“作答 → 判分 → 错因确认 → 订正 → 再练 → 掌握度/复习更新”的数据库可追溯闭环。

### v2.0 — 作业图片与手写 OCR

范围：

- 上传图片或 PDF，异步完成 OCR、版面分析、题目分割和结构化解析。
- 保存文件哈希、页码、区域坐标、OCR 原文、置信度和人工修订记录。
- 印刷体、手写体和数学公式分别评测，不用总体平均掩盖薄弱类型。
- OCR 结果进入待确认区，确认后进入 v1.9 的题目、错题和任务流程。

验收：同一文件幂等处理，失败任务可重试；确认前不改变学生画像和掌握度。

### v2.1 — 全学段与全学科发布

范围：

- 按“学科 × 学段 × 教材版本”建立独立发布包。
- 每个发布包配置解析、知识点类型、难度体系、提示词和固定评测集。
- 跨科画像区分全局学习偏好和学科专属掌握状态。
- 发布门禁包括来源完整性、知识抽样、图谱关系、检索和路径正确性。

验收：每个发布包单独通过门禁后才能激活；未发布学科不出现在可选范围中。

### v2.2 — 家长端、周报与提醒

范围：

- 家长与学生关系需要邀请或授权，家长只能查看授权学生。
- 周报展示目标完成、真实练习、错题、掌握变化和待复习任务，并保留数据来源。
- 站内提醒支持去重、关闭、静默时间和送达记录；外部渠道另行授权。
- 提供授权撤回、数据导出、数据删除和操作审计。

验收：报告数字可追溯，提醒不重复，撤回授权立即生效，导出和删除覆盖关系库与向量库。

### v2.3 — 教师端与班级学情

范围：

- 教师、班级、学生加入、课程和作业均有明确授权边界。
- 教师可发布作业、查看提交和针对性干预，不直接修改学生事实记录。
- 班级学情使用聚合数据，个人详情只对授权范围开放。
- 记录教师查看、导出、批改和干预操作。

验收：跨班级和跨教师访问被拒绝；聚合结果可以回查组成记录；学生退出班级后权限及时失效。

### v2.4 — 可复现评测与统一质量门禁

保留原 v1.7 的五组实验，并扩展覆盖诊断计划、练习判分、OCR 分类型、角色权限和数据删除。完整数据集先生成候选及标注模板，再由人工复核；AI 生成内容不能标记为人工标注。

统一质量门禁执行迁移检查、后端离线测试、前端测试与构建、双库审计、固定回归评测和报告汇总。外部 LLM 与付费评测使用显式开关。

验收：所有指标可从版本化数据和脚本重算；任一失败步骤返回非零退出码；没有真实样本时明确标记模拟或离线结果。

### v2.5 — 毕设、作品集、部署与最终交付

保留原 v1.8 的 Docker、README、论文、答辩和演示范围。最终材料只引用 v2.4 的版本化结果，并完成冷启动、健康检查和三次按脚本演示。

验收：代码、数据库迁移、测试、评测、README、论文和简历中的事实一致；最终验收报告列出所有未完成项和边界。

## 4. 功能取舍

- 语音辅导移入 v2.5 之后的候选功能池。它具有展示价值，但当前优先级低于诊断、作答、判分和纠错。
- 不单独增加“运营后台”版本。教材审核、纠错队列和权限审计分别归入 v1.7、v2.2、v2.3。
- 不在评测前一次性编译全部教材。每个发布包独立验收。
- 不引入没有当前负载依据的 Redis、Celery 或微服务拆分；异步任务先采用可持久化、可重试的最小实现。

## 5. 文档改动范围

正式改写《个性化教育-产品迭代路线图》时：

1. 更新主线流程图和总周期说明。
2. 用 v1.7～v2.5 九个版本替换原 v1.7、v1.8 和 v2.0～v2.5。
3. 更新版本总览、系统设计完成项映射和暂不进入主线事项。
4. 保留 v1.7 暂停记录的事实，但移动到 v2.4 的历史说明中，注明当时没有生成数据或指标。
5. 不修改 v1.4～v1.6 的完成状态、提交号和验收数字。
