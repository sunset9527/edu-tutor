# EduTutor v1.7 教材治理与回答证据实施计划

日期：2026-10-16  
依据：`docs/superpowers/specs/2026-10-15-v1.7-knowledge-governance-design.md`  
执行方式：按顺序持续执行，无须逐任务批准；所有行为遵循 RED → GREEN → REFACTOR。

## 总体约束

- 不改写 v1.4～v1.6 已有验收事实和评测数字。
- 不删除现有 857 个知识点；迁移为明确标注来源缺口的 legacy 数据。
- 新生产行为必须先有能因功能缺失而正确失败的测试。
- 关键数据库行为使用真实 MySQL；向量测试使用隔离或可清理数据。
- 每个里程碑先跑专项测试，再跑后端离线回归与前端门禁。
- 真实 LLM/OCR 调用只在最终教材样例验收中显式执行；离线门禁不得隐式计费。

## 任务 0：记录实施前基线

**读取：** 后端与前端现有测试配置。  
**动作：**

1. 运行后端离线门禁：
   `python -m pytest -k "not test_chat_flow and not test_extractor_returns_json" -q`
2. 运行前端 `npm run typecheck`、`npm test`、`npm run build`。
3. 运行 Alembic `current`/`heads` 和只读双库审计。
4. 把基线结果记入实施日志；若已有失败，先区分环境问题与回归问题。

## 任务 8：active 知识检索与证据充分性

- `backend/app/agents/chat_graph.py`

**RED：**

- 流式和非流式路径调用同一知识检索/充分性规则。

**GREEN：** 抽取共享 turn preparation/evidence recorder，保持既有记忆事件和会话恢复行为。

**RED：**

**GREEN：** 实现工单状态机和按类型处理器。
