# EduTutor v1.5 验收报告

验收日期：2026-10-12
版本主题：记忆智能与个性化路径
结论：通过

## 交付范围

- 记忆向量候选按相似度、新近度、遗忘保留率和置信度统一评分。
- 四项评分权重、三路注入限额和新近度时间尺度进入动态配置；每次追踪记录配置值及归一化后的实际权重。
- 追踪返回候选记忆、分项分数、最终分数、排名、采用状态和未采用原因；命中项更新 `last_accessed_at`。
- 画像、相关记忆和最近事件独立限额，并按记忆 ID 跨通道去重；画像快照不再重复展开同一薄弱点。
- 正确/错误练习驱动知识点掌握度状态机和复习计划；错题事实、掌握记忆和复习计划在同一 MySQL 事务中提交，Chroma 失败时回滚或补偿。
- 相同 `有效策略` 的独立消息证据达到 `consolidation_threshold` 后才从 candidate 激活为 procedural 记忆；重复处理同一消息不会累计证据。
- 对话提取记忆保存来源会话、来源消息、提取版本、模型和提取时间。
- `POST /api/sessions/{session_id}/end` 幂等结束会话，生成确定性提取式摘要及 episodic 记忆。
- LangGraph 不再把内存 checkpointer 作为恢复来源；每轮从 MySQL 消息表重建短期上下文。
- `GET /api/knowledge/path/{kp_id}?student_id=...` 校验账号归属，并依据前置边、掌握度、薄弱点、错题和到期复习返回逐步原因与记录 ID；图谱无证据时明确返回 `evidence_gap`。

本版本没有新增表字段。溯源和证据计数使用现有 `structured_data` JSON，因此不需要 Alembic 迁移。

## 固定三学生、九会话场景

执行：

```powershell
python -X utf8 scripts/generate_v15_evidence.py
```

脚本创建临时知识点、三名学生和每人三次会话，完成以下事实链后清理临时数据库记录：

1. 第一次会话分别写入不同薄弱点和学习偏好。
2. 第二次会话从长期记忆取回各自画像。
3. 第三次会话用正确或错误练习更新掌握状态和知识点复习任务。

面对同一目标“一元一次方程”，实际结果为：

| 学生 | 第三次会话事实 | 待复习知识点 | 生成路径 |
|---|---|---:|---|
| 甲 | 整数运算连续两次正确，达到熟练 | 1 | 等式性质 → 一元一次方程 |
| 乙 | 等式性质连续两次正确，达到熟练 | 1 | 整数运算 → 一元一次方程 |
| 丙 | 整数运算、等式性质各一次错误 | 2 | 整数运算 → 等式性质 → 一元一次方程 |

完整临时记录 ID、三次会话 ID、取回画像、状态转换和逐步原因见 `three-student-path-comparison.json`。

- Vite 仍提示部分 chunk 大于 500 kB，以及依赖中的 PURE 注释位置问题。
